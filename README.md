# 山西联通 DIYP 频道列表

把 [sheriffcheng-gif/my-iptv](https://github.com/sheriffcheng-gif/my-iptv) 持续更新的山西联通组播源，自动整理成 **DIYP 影音 / 电视端可直接订阅的分类节目列表**。

这个仓库只做一件事：把上游 M3U 里没有分类、名称里带 HD/SD 的频道，整理成电视上好找、好切换的列表。不需要电脑或 NAS 常开，全部由 GitHub Actions 定时完成。

## 📺 订阅地址（这就是带分类的直播源）

**播放器里只需要填下面这一个地址**，它返回的就是完整的节目列表 + 每路频道的播放地址：

```
https://cdn.jsdelivr.net/gh/Kimbe6688/shanxi-iptv-diyp@main/山西联通DIYP.txt
```

个别播放器不认中文路径时，用等价的 URL 编码版：

```
https://cdn.jsdelivr.net/gh/Kimbe6688/shanxi-iptv-diyp@main/%E5%B1%B1%E8%A5%BF%E8%81%94%E9%80%9ADIYP.txt
```

> **不需要再填 M3U，也不需要填上游项目地址。** DIYP 格式把「分类 / 频道名 / 播放地址」写在同一行里，
> 分类只是把这些行重新排序编号，播放地址一直都在。填一个订阅 URL，频道列表和直播源就都拿到了。

备用地址（jsDelivr 缓存未刷新时）：

```
https://raw.githubusercontent.com/Kimbe6688/shanxi-iptv-diyp/main/%E5%B1%B1%E8%A5%BF%E8%81%94%E9%80%9ADIYP.txt
```

### GitHub Proxy 加速（可选）

如果 GitHub / jsDelivr 访问慢，可以在 raw 地址前加代理前缀：

```
https://gh-proxy.com/https://raw.githubusercontent.com/Kimbe6688/shanxi-iptv-diyp/main/%E5%B1%B1%E8%A5%BF%E8%81%94%E9%80%9ADIYP.txt
```

jsDelivr 在国内一般可以直接访问，优先用上面的主地址即可。

## 📋 节目列表长什么样

```
本省,#genre#

002 山西卫视SD,http://61.134.254.2:9003/rtp/226.0.2.11:8000
003 山西卫视SD,http://61.134.254.2:9003/rtp/226.0.2.189:9424

卫视,#genre#
001 山西卫视HD,http://61.134.254.2:9003/rtp/226.0.2.152:9128
002 重庆卫视HD,http://61.134.254.2:9003/rtp/226.0.2.174:9304
003 江苏卫视HD,http://61.134.254.2:9003/rtp/226.0.2.176:9320
```

- `分类名,#genre#` 是分组标题，输出顺序固定：**本省 → 央视 → 影院 → 4K → 卫视 → 其他**
- 每行 `001 频道名,http://地址`：三位序号在同分类内从 001 自动编号，**逗号后面就是实际直播源**
- 同一频道的 HD / SD 多路源全部保留、各自独立成行；某一路不稳时，用遥控器左右键就能切到下一路

## ❓ 填了 .txt 之后还会更新吗

**会，地址不用换，也不用重新导入。**

你在播放器里填的是**订阅 URL**，不是下载一次的本地文件。播放器每次刷新订阅都会重新拉取这个地址。完整链路：

```
上游 my-iptv 更新 山西联通.m3u
        ↓
本仓库 workflow 定时拉取最新 M3U
        ↓
按规则重新分类、生成 山西联通DIYP.txt 并提交回仓库
        ↓
播放器刷新订阅 → 拿到新的频道列表和新的播放地址
```

上游的 M3U 地址是 `https://raw.githubusercontent.com/sheriffcheng-gif/my-iptv/main/m3u/山西联通.m3u`（在上游仓库，不需要填进播放器）。上游换频道、换地址，我们下一次构建时 TXT 会跟着变。

一点注意：jsDelivr 有缓存，刚更新完可能要等一会儿才刷出来；想立刻拿最新就用上面的 raw 地址。另外上游的定时任务实际常有数小时延迟，所以 TXT 可能比上游 M3U 滞后一轮，再下一次构建会补上。

## 🔄 更新机制

- 上游在 workflow 里声明每天 UTC 00:00 / 12:00 各更新一次
- 本仓库配置在**其后 5 分钟**（UTC 00:05 / 12:05，北京时间 08:05 / 20:05）自动构建
- 但上游的 GitHub Actions 定时任务实际经常延迟数小时才跑完（观察到 UTC 05:00 前后、17:00～19:30 都有），
  所以「+5 分钟」只是配置上的对齐，**实际可能取到上一轮的 M3U**，下一次构建才会补上
- 构建流程：拉取 M3U（raw → gh-proxy → ghfast 三重兜底）→ 分类 → 写出 TXT → 提交回仓库
- TXT 内容没有变化时不产生提交；`concurrency` 保证同一时间只跑一个构建

## 🗂️ 分类规则

匹配优先级（先匹配先生效，**与上面的输出顺序是两回事**）：

| 顺序 | 分类 | 关键词 |
| --- | --- | --- |
| 1 | 4K | 4K / 2160 / 超清 / 8K |
| 2 | 影院 | CHC / 电影 / 剧场 / HBO / 风云 … |
| 3 | 央视 | CCTV / 央视 / CGTN / 中国教育 … |
| 4 | 本省 | 山西 / 黄河 / 太原、大同、临汾等各地市县名 … |
| 5 | 卫视 | 卫视 |
| 6 | 其他 | 以上都不匹配 |

- 「本省」按 山西卫视 → 山西黄河 → 山西经济与科技 → 山西影视 → 山西社会与法治 → 山西文体生活 优先排序，其余按名称顺序
- 「卫视」同样把 山西卫视 置顶；上游源里没有该频道时自动跳过，不硬塞
- 播放地址按 URL 去重（同一地址只保留一行）。唯一的例外是山西卫视：为了在「本省」和「卫视」两个分类都能置顶找到它，会在这两处各放一次，用的是同一路高清源 —— 这是有意为之，不是去重失效

## 📝 使用说明

- 播放地址来自运营商组播源，经 HTTP 代理转出，**一般需要在山西联通宽带网络内使用**；其他运营商或外网环境可能无法播放
- 本仓库只整理频道列表，不托管、不提供任何直播流，也不保证源的可用性
- 频道数量随上游变化，不在此写死；以订阅地址返回的 TXT 为准
