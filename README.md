# 山西联通 DIYP 频道列表

把 [sheriffcheng-gif/my-iptv](https://github.com/sheriffcheng-gif/my-iptv) 持续更新的山西联通组播源，整理成电视端更好找台的**分类节目列表**。

这个仓库只做一件事：上游 M3U 里所有频道都归在同一个分组（`group-title="山西联通"`）、名称还带 HD/SD，找台不方便；这里把它整理成带分类、老人也能直接用的列表。不需要电脑或 NAS 常开，全部由 GitHub Actions 定时完成。

## 🚀 使用方法

**VsTV、DIYP 影音这类「空壳 APP」**本身不带任何频道，装好后在设置里填一个订阅地址即可。下面两种方式**任选其一**，不要同时填。

### 1. M3U 文件（上游原源）

```
https://raw.githubusercontent.com/sheriffcheng-gif/my-iptv/main/m3u/山西联通.m3u
```

- 由上游 `my-iptv` 直接提供，频道最全，自带台标和 EPG 节目单
- 标准 M3U，支持 M3U 的播放器都能用
- 上游一更新，播放器刷新订阅就拿到最新的，不经过本仓库
- 缺点是所有频道挤在一个分组里，找台要按原始顺序翻

> 播放器不认中文路径时，M3U 也有等价的编码版：
>
> ```
> https://raw.githubusercontent.com/sheriffcheng-gif/my-iptv/main/m3u/%E5%B1%B1%E8%A5%BF%E8%81%94%E9%80%9A.m3u
> ```

### 2. TXT 文件（备选：带分类整理）

```
https://cdn.jsdelivr.net/gh/Kimbe6688/shanxi-iptv-diyp@main/山西联通DIYP.txt
```

- 本仓库在上游基础上整理出分类、三位序号、「本省 / 卫视」双分类置顶，电视上更好找台
- DIYP 格式，VsTV / DIYP 影音等可直接订阅
- 每行 `001 频道名,http://地址` 的逗号后面就是实际播放地址，**不需要再另外填 M3U**

> **播放器不支持中文路径时**，用下面这个等价的 URL 编码版（内容完全一样）：
>
> ```
> https://cdn.jsdelivr.net/gh/Kimbe6688/shanxi-iptv-diyp@main/%E5%B1%B1%E8%A5%BF%E8%81%94%E9%80%9ADIYP.txt
> ```

备用地址（jsDelivr 缓存未刷新时）：

```
https://raw.githubusercontent.com/Kimbe6688/shanxi-iptv-diyp/main/%E5%B1%B1%E8%A5%BF%E8%81%94%E9%80%9ADIYP.txt
```

https://gh-proxy.com/https://raw.githubusercontent.com/sheriffcheng-gif/my-iptv/main/m3u/山西联通.m3u

jsDelivr 在国内一般可以直接访问，TXT 优先用上面的主地址即可。

## 📋 节目列表长什么样

TXT 订阅地址返回的内容（下面是从当前文件里截取的真实片段，未做改写）：

```
本省,#genre#
001 山西卫视HD,http://61.134.254.2:9003/rtp/226.0.2.152:9128
002 山西卫视SD,http://61.134.254.2:9003/rtp/226.0.2.11:8000
003 山西卫视SD,http://61.134.254.2:9003/rtp/226.0.2.189:9424
004 山西黄河HD,http://61.134.254.2:9003/rtp/226.0.2.235:9792

卫视,#genre#
001 山西卫视HD,http://61.134.254.2:9003/rtp/226.0.2.152:9128
002 重庆卫视HD,http://61.134.254.2:9003/rtp/226.0.2.174:9304
003 江苏卫视HD,http://61.134.254.2:9003/rtp/226.0.2.176:9320
```

- `分类名,#genre#` 是分组标题，输出顺序固定：**本省 → 央视 → 影院 → 4K → 卫视 → 其他**
- 每行 `001 频道名,http://地址`：三位序号在同分类内从 001 自动编号，**逗号后面就是实际直播源**

### 为什么列表里有好几个「山西卫视」

上游源里同一个频道常常有多路地址、多种清晰度（HD / SD）。本仓库**按 URL 全部保留，并列成独立条目**，没有合并成一个频道再让播放器内部切源。

这是**刻意为老人做的**：

- DIYP 这类播放器通常把备用源藏在同一个频道名下，要按左右键或进菜单才能切换。年轻人会这么找，老人不会。
- 遇到某一路卡顿，老人多半只会直接换台。把每路源做成列表里**看得见、点得到的独立频道**，不稳时按一下下一条就是另一路源，不用记任何操作、也不用进菜单。
- 所以名字保持原样（HD / SD 都保留），不编号、不合并，看到几个就是几路，一目了然。

同理，「本省」和「卫视」两个分类都把 山西卫视 放在第一条，是为了在常看的两个分组里第一眼就能找到；上游源里没有该频道时自动跳过，不硬塞。

## ❓ 填了订阅地址之后还会更新吗

**会，地址不用换，也不用重新导入。** 填的是订阅 URL，不是下载一次的本地文件；播放器每次刷新订阅都会重新拉取。

两种方式的链路稍有不同：

```
方式 1（M3U）：上游更新 M3U ──────────────────────→ 播放器刷新，立即拿到最新

方式 2（TXT）：上游更新 M3U
                    ↓
              本仓库 workflow 定时重新分类、生成 TXT 并提交回仓库
                    ↓
              播放器刷新订阅 → 拿到新的频道列表和新的播放地址
```

- 直接填 M3U 最实时；填 TXT 会多等我们一次构建（每 12 小时一次），换来的是分类和置顶
- jsDelivr 有缓存，刚更新完可能要等一会儿才刷出来；想立刻拿最新就用 raw 地址
- 上游的定时任务实际常有数小时延迟，所以 TXT 可能比上游 M3U 滞后一轮，再下一次构建会补上

## 🔄 更新机制

- 上游在 workflow 里声明每天 UTC 00:00 / 12:00 各更新一次
- 本仓库配置在**其后 5 分钟**（UTC 00:05 / 12:05，北京时间 08:05 / 20:05）自动构建
- 但上游的 GitHub Actions 定时任务实际经常延迟数小时才跑完，所以「+5 分钟」只是配置上的对齐，
  **实际可能取到上一轮的 M3U**，下一次构建才会补上；追求实时就直接用上面的 M3U
- 构建流程：拉取 M3U（raw → gh-proxy → ghfast 三重兜底）→ 分类 → 写出 TXT → 提交回仓库
- TXT 内容没有变化时不产生提交；`concurrency` 保证同一时间只跑一个构建

## 🗂️ 分类规则

匹配优先级（先匹配先生效，**与输出顺序是两回事**）：

| 顺序 | 分类 | 关键词 |
| --- | --- | --- |
| 1 | 4K | 4K / 2160 / 超清 / 8K |
| 2 | 影院 | CHC / 电影 / 剧场 / HBO / 风云 … |
| 3 | 央视 | CCTV / 央视 / CGTN / 中国教育 … |
| 4 | 本省 | 山西 / 黄河 / 太原、大同、临汾等各地市县名 … |
| 5 | 卫视 | 卫视 |
| 6 | 其他 | 以上都不匹配 |

- 「本省」按 山西卫视 → 山西黄河 → 山西经济与科技 → 山西影视 → 山西社会与法治 → 山西文体生活 优先排序，其余按名称顺序
- 「卫视」同样把 山西卫视 置顶；上游源里没有该频道时自动跳过
- 播放地址按 URL 去重（同一地址只保留一行）。唯一的例外是山西卫视：为了在「本省」和「卫视」两个分类都能置顶找到它，会在这两处各放一次，用的是同一路高清源

## 📝 使用说明

- 播放地址来自运营商组播源，经 HTTP 代理转出，**一般需要在山西联通宽带网络内使用**；其他运营商或外网环境可能无法播放
- 本仓库只整理频道列表，不托管、不提供任何直播流，也不保证源的可用性
- 频道数量随上游变化，不在此写死；以订阅地址返回的 TXT 为准
